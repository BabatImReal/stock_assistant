### TASK 2 — PROPOSAL: point-in-time universe + breadth (doc §5.3). NO CODE.

**A. The tradeable set T(D).** Symbol s is in T(D) when `bar_raw` has (s, D)
with `matched_volume > 0`, the row is not `date_shifted` (config
`exclude_date_shifted`), and D is not inside an `excluded_window` for s.
- *Why rows, not listing status.* We have no reliable listed/suspended table:
  `symbol_exchange` carries no suspensions, and its spans use the current
  exchange (found this run). A row with volume is first-hand evidence the stock
  traded. A missing row means suspended, not yet listed, or delisted, and each
  of those is correctly outside T(D).
- *Zero-volume rows are out.* There are 4,399 since 2012, and 98.5% sit at the
  previous close. They are placeholders, and counting them would pad
  "unchanged".
- *Survivorship.* A delisted symbol is in T(D) on every day it actually traded.
  That discharges the universe-membership half of G11. It does NOT fix CafeF's
  uneven delisted history (for example, 11 single-row stubs).
- *Whole market, no per-exchange split*: `exchange` is not historical.
- Size since 2012: 341 to 1,135 symbols per date, median 665.

**B. The PIT liquid universe L(D) ⊆ T(D).** s is in L(D) when s is in T(D),
and over the trailing **60 SESSIONS ending at D** (the same convention as every
measure: lookback prior rows plus today, all known at D's close, nothing after D
read) both of these hold:
- it traded (in T) on ≥ 40 of them;
- its mean traded value on those days is ≥ `min_avg_matched_value`.

Details:
- The window is counted in sessions from the calendar, not in
  `lookback_days × 1.5` calendar days, which is the approximation in today's
  copies.
- Traded value = close × matched volume. By the G1 invariant, raw × raw equals
  adjusted × adjusted on CafeF rows. On backfilled (vnstock) rows only the
  adjusted price exists. Adjusted close × volume **understates** the value there,
  so clearing the floor on it is a true pass. It can only exclude wrongly, never
  include wrongly. (Q3) This holds only when it reads `bar_raw`. `bar_adjusted`
  on those spans carries the seam rescale (factor up to 2.02, G17), which can
  lift the price ABOVE raw.
- *Gaps*: a suspension inside the window does NOT NaN liquidity. The
  days-traded count is what measures it. A mostly-suspended stock simply fails
  the 40/60 test.
- Thresholds stay provisional pending G10. They are read from
  `config/rules/universe.yaml` as today.

**C. Where it lives, and computed or cached.** Recommendation: **recompute on
demand**. New module `data/universe.py` with `tradeable(conn, start, end)` and
`liquid(conn, start, end)`. Each is one SQL pass with window functions over
about 2.5M rows, returning a long frame
(trade_date, symbol, traded_value, days_traded, liquid).
- It reads only `bar_raw` + `excluded_window`, so it is **build-independent**
  and nothing can go stale.
- Why no cached table: this run just showed a derived table (`trading_day`)
  drifting because nobody re-derived it. Cache later only if timing proves it
  necessary. (Q1)

**D. Relation to `liquid_symbols()`.** Six separate SQL copies define "liquid"
today: `features/bars.py` and five scripts. `bars.liquid_symbols(conn)` becomes
"L(latest date)" from `data/universe.py`, so reporting and research share one
definition. Research statistics (base rates, funnel step 2, the backtest) filter
by **L(D) at each D**, never by `liquid_symbols()`. The five one-time scripts
have already run and have recorded results. Recommendation: leave them and add
a pointer comment. (Q5)

**E. Breadth on the universe.** For each D, count symbol s when all of these
hold:
- s is in U(D), where U is L or T (Q2);
- its previous bar is the **immediately preceding session** (`gap_before == 0`);
- that previous bar was itself tradeable (volume > 0, not excluded or shifted).

A stock resuming after a suspension is compared with a stale close, so it is
not counted that day. That is the no-gap rule with a declared lookback of 1.

Then:
- Direction = sign of adj_close(D) / adj_close(prev) − 1 on the
  **current promoted build's ADJUSTED close**, with |x| < 1e-9 counted as
  unchanged. An ex-dividend drop is therefore not a decline. Breadth is
  build-scoped for that reason; the universe is not.
- Daily counts: advancers, decliners, unchanged, n.
- Two measures in `MARKET_REGISTRY`, computed once and joined by trade_date
  like the index regime:
  - `breadth_advance_share` = adv / (adv + dec), lookback 0. Unchanged is left
    out of the denominator, because thin names print unchanged a lot.
  - `breadth_advance_share_10d` = mean of the daily share over 10 sessions,
    lookback 9.

  Parameters are fixed now, not tuned.
- *Data-defect guard*: breadth is NaN on a date where n falls below a share of
  its trailing 20-session median. A lost exchange file (2025-05-05 HNX, about
  −22% of n) would otherwise bias that day. The threshold is a data-quality
  choice. I propose to set it from the measured distribution of
  n / trailing-median BEFORE any breadth statistic is computed.
- *Frames*: breadth gets its own calendar-aligned frame with its own
  `gap_before`, separate from the index frame. An index gap (the 2018 HOSE
  halt) should not NaN breadth, and a breadth defect should not NaN the index
  measures. `compute_market` takes both frames, and each market measure's
  declared `needs` selects its frame. (Q4)
- *No look-ahead*: every quantity at D reads rows ≤ D. The adjusted-close ratio
  equals the raw ratio times the factor ratio, which is the same adjustment
  every measure already uses (G1).

**F. Tests. Each one fails without its guard.**
1. Ex-dividend day: raw close drops while the adjusted close is flat. It must

2. A symbol resuming after a suspension is not counted that day.
3. A zero-volume placeholder is not in T and not counted.
4. A delisted symbol is in T up to its last day and absent after.
5. Truncation: L(D) and breadth(D) stay identical when every row after D is
   deleted.
6. The liquidity window counts sessions, not calendar days (a Tet week).
7. Live DB: L ⊆ T, and |T(D)| ≤ the calendar's symbol count on D.

### SECTOR PROPOSAL (doc §5.4). NO CODE until S1–S6 are answered.

**A. Where membership comes from.**
- **Not in our data.** Not in `bar_raw`, `symbol`, the CafeF bulk or per-stock
  files, or CafeF's index file (VNINDEX and HNX-INDEX only).
- **Proposed source: vnstock VCI `symbols_by_industries()`, taxonomy ICB**
  (legacy 4-digit codes, levels 1–4; the classification HOSE and the VN
  brokers use).
  - *Cost*: free, one call, already installed and keyed.
  - *Coverage*: all active symbols; 366 of 495 inactive; 99.0% of liquid
    stock-days since 2012. 19 of the 825 ever-liquid symbols are missing, all
    delisted.
  - *Reliability*: vendor data (VCI) served through an unofficial community
    library. Refresh policy undocumented. Nothing guarantees it stays
    available.
- **Second-source reconciliation (CLAUDE.md)**: vnstock KBS, a different 2-digit
  taxonomy, so only a coarse check is possible. Overall: 74.6% modal agreement
  at ICB level 2. The doc's named groups: banks 24/25, securities 32/32, real
  estate 69/83; the 12 differences are developers that ICB files under
  construction, which is a real taxonomy boundary. I propose we accept that
  and store KBS alongside as the reconciliation record.
- *Not found free*: HOSE sector-index history (VNFIN, VNREAL, …), and any
  dated ICB history. Paid vendors are not checked; say if you want me to price
  one.

**B. Point-in-time? NO: current only.** No date field, no reclassification
history. Plainly:
- **Label look-ahead**: applying today's ICB to 2012 classifies a company by
  what it became. A firm that pivoted into real estate in 2020 would count as
  real estate in 2014.
- **Survivor bias**: 129 of 495 inactive symbols have no label, so their days
  drop out of sector aggregates. Small (about 1% of liquid stock-days), but
  the bias runs toward survivors.
- **Treatment, like the exchange-label problem**:
  1. Store the snapshot with `as_of` (the fetch date) and `source`.
  2. Every sector value computed for a date BEFORE the first snapshot carries
     the flag `sector_label = current_as_of_<date>`, recorded in the
     FeatureSet parameters, so it is in the fingerprint and visible in every
     result.
  3. Start collecting real point-in-time snapshots FORWARD (a periodic fetch;
     scheduling it belongs with the nightly job, i.e. after the hardening
     slice). From the first snapshot on, membership is genuinely
     point-in-time.

**C. Which level.** Recommended: **ICB level 2.** Among today's liquid stocks
that is 19 groups of 2–47 (median 7), and it matches the doc's groups: banks,
real estate, financial services (28/31 are brokers), construction &
materials. Its weak spot: steel is only 8 of 17 in "basic resources" (with
paper and mining). Level 4 isolates steel, but groups get tiny: at level 3,
the median group is 4 and the smallest is 1.

**D. How it fits the registry: both, split by role.**
- A **SECTOR frame**, computed once per run like breadth. It covers
  sessions × sector, from the universe rows plus the labels:
  - the sector's daily return = the MEDIAN daily adjusted return of the members
    that traded today AND the previous session (the breadth rule). It is
    equal-weighted by necessity: we have no share counts, so no cap weights.
    The median resists thin-stock noise;
  - the sector advance share;
  - the members counted.
- **Per-symbol measures**, joined on `(trade_date, the symbol's sector)`:
  - `sector_change_20d`: the compounded sector return over 20 sessions ("is
    my sector strengthening?", the doc's exact question);
  - `sector_advance_share_10d`;
  - `stock_vs_sector_20d` = the stock's 20-session change minus its sector's
    (relative strength).
- **Market-level rotation** (which sector leads) is a REPORT view, not a
  measure. Not proposed now.
- *Mechanics*: add `frame="sector"` to the existing market-measure machinery,
  with a join key of `(trade_date, sector)`. The bar loader gains a `sector`
  column. It is the same pattern as breadth; the alternative is a third
  registry.
- It also gives the **§7.1 fallback group** (stock → sector → market) for base
  rates. A sector with fewer than k members falls back to the market (k is
  tied to G10).

**E. Guards.**
- *No look-ahead*: every window is trailing, and the frame reads rows ≤ D.
  Declared lookbacks include the frame's reads: +1 for "traded the previous
  session", plus the 20- or 10-session window. The tests are the breadth
  pattern: truncation, and changing every row outside the declared window.
- *Gaps*: a member counts on D only if it traded the previous session. The
  frame is aligned to the calendar, so it has no calendar gaps.
  `stock_vs_sector_20d` also needs the stock's own window to be clean (gap and
  excluded guard).
- *Thin sector-days*: NaN when fewer than `min_members` (e.g. 3) are counted,
  or the count falls below a share of its trailing median. A lost exchange file

### EXCHANGE-LABEL PROPOSAL (item 6). NO CODE until X1–X4 are answered.

**What is available.**
- *Our data*: partly historical. CafeF kept both spans for the 116 Class A
  transfers, and those are dated correctly. But:
  - the 46 vnstock backfills carry today's exchange (ACB = HOSE for 2006–2020;
    it was on HNX);
  - CafeF sometimes re-files a transferred stock's whole history under its new
    exchange (DPG is in the HSX file from 2017, yet traded while HOSE was
    halted on 2018-01-23).
- *vnstock KBS `overview().listing_date`*: **dated, but for the LAST move
  only.** It is the date the symbol joined its current exchange. Confirmed on
  7 symbols:
  - HPG, VNM, PVS = our first bar (never moved);
  - DPG 2018-05-22, SHB 2021-10-11, VCG 2020-12-29, VIX 2021-01-08 (known
    transfers).

  It does not say which exchange the symbol was on before (HNX or UPCoM), and
  multi-hop moves (UPCoM → HNX → HOSE) lose the earlier hop. Cost: one call
  per symbol, about 1,700 calls, about 30 min.
- *vnstock VCI `events()`*: only the latest 50 events and no transfer type.
  Not usable. `Listing.symbols_by_exchange()`: current only.
- So: **dated for the current span, current-only before it**, except where
  CafeF's Class A spans supply the earlier hop.

**Proposed treatment (like sector: flag as a hard gate).**
1. Store dated spans in `symbol_exchange`, with a `source` of 'kbs_listing':
   current exchange from `listing_date`. The earlier span comes from CafeF
   Class A where available, otherwise **exchange = unknown**. Reconcile: for
   Class A symbols, the CafeF span boundary must match KBS `listing_date`, and
   mismatches are flagged.
2. A resolver `exchange_on(symbol, date)`, like `sectors.assign`, returns the
   exchange and `exchange_label_current` (True where the exchange before the
   last move is unknown, and today's is being borrowed).
3. **Consumers of per-exchange rules take the flag:**
   - the price-limit check (`checks.limit_sql`) and first-day limits;
   - `forward_returns.is_at_ceiling / is_at_floor` (B1);
   - fillability;
   - the backtest's entry/exit rules.

   A stock-day judged with a borrowed exchange is flagged, and the backtest
   QUARANTINES it (the `quarantine_flagged` pattern) rather than modelling a
   ±7% limit for a stock that was really on ±10%.
4. Not proposed as a source: inferring the exchange from the size of daily
   moves (a 7–10% move implies not HOSE). That is a useful consistency CHECK,
   but a heuristic cannot be the label.
